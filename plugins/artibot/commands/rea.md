# /rea

REA(Reverse Engineer Anything, morluto/rea, MIT)로 앱·바이너리·웹 페이지를 역공학 조사한다. 이 커맨드는 얇은 래퍼다 — 조사 방법은 업스트림 스킬이 정하고, 여기서는 연결돼 있으면 그 스킬을 읽게 하고 연결돼 있지 않으면 업스트림 절차대로 연결시키는 일만 한다. 스킬 문구와 엔진은 한 버전(rea-agents@6.7.0)으로 짝지어 고정돼 있다.

> **이중 용도**: REA 는 합법적이고 허가된 분석(보안 연구, 악성코드·사고 분석, 상호운용, 보존, 본인 소유이거나 분석 권한이 있는 소프트웨어 점검)을 위한 도구다. DRM·라이선스·안티치트 우회, 접근통제 우회, 허가 없는 대상 분석에는 쓰지 않는다. 책임과 범위는 [업스트림 DISCLAIMER](../vendor/rea/DISCLAIMER.md) 를 따른다.

## Arguments

`$ARGUMENTS` = 조사 대상(앱 이름, 파일·폴더 경로, 웹 페이지 URL)과 알고 싶은 것. 대상이 비었거나 "내 앱" 처럼 불분명하면 먼저 어떤 대상인지 묻는다. 대상을 대신 고르거나 예시 앱을 쓰지 않는다. 사용자가 지정하지 않은 파일·프로그램은 열지도 실행하지도 않는다. 대상이 `http://` 나 `https://` 로 시작하는 주소면 4 의 웹 대상 절차를, 경쟁·참고 앱을 비교·벤치마킹하는 요청이면 5 의 7축 체크리스트를 함께 쓴다.

## 1. REA 가 연결돼 있는가

이 세션의 툴 목록에 `mcp__rea__` 로 시작하는 툴이 있으면 연결된 것이다(지연 로드 목록이면 ToolSearch 로 확인). 있으면 2 로, 없으면 3 으로 간다.

## 2. 연결돼 있을 때 — 업스트림 스킬을 그대로 따른다

1. 스킬을 Read 한다: `${CLAUDE_PLUGIN_ROOT}/vendor/rea/skill/SKILL.md` (호스트가 이 커맨드를 불러올 때 플러그인 경로를 채워 넣는다). 변수 참조가 그대로 보이거나 파일이 없으면 `rea setup` 이 설치한 사본 — 홈 폴더의 `.claude/skills/reverse-engineer-anything/SKILL.md` — 을 Read 한다(같은 내용). 둘 다 없으면 연결된 서버의 툴 목록과 입력 스키마를 따르고, 스킬을 읽지 못했다고 알린다.
2. SKILL.md 가 시키는 대로 `$ARGUMENTS` 를 조사한다. 문구를 고치거나 요약으로 갈음하지 않는다. SKILL.md 가 가리키는 `references/*.md` 는 SKILL.md 와 같은 폴더에서, 해당 주제가 나올 때만 Read 한다.
3. 대상 프로그램 실행·런타임 관찰·장치 조작은 사용자가 요청한 범위 안에서만 한다. REA 툴 호출은 업스트림과 같이 호스트 권한 확인을 거친다 — 이 커맨드는 REA 툴을 사전 승인하지 않는다.

## 3. 연결돼 있지 않을 때 — 업스트림 절차 그대로

먼저 사용자에게 REA 가 이 세션에 연결돼 있지 않다고 알린다. 아래는 업스트림 스킬(SKILL.md 의 "Connect only when needed")과 같은 순서다.

1. **Node 검사**: `node --version` 이 `^22.19 || ^24.11 || >=26` 이어야 한다(업스트림 engines). 미달이거나 node 를 못 찾으면 이유를 알리고 여기서 멈춘다. REA setup 은 Node 를 설치하거나 올리지 않는다.
2. **진단** (설정을 바꾸지 않는다. npx 가 패키지를 받아 npm 캐시에 쓴다):
   ```bash
   npx -y rea-agents@6.7.0 doctor --client claude_code --json
   ```
   등록이나 스킬이 어긋나 있으면 종료 코드가 1 이다(실측). 명령 실패가 아니라 진단 결과이니 JSON 의 classification 을 읽는다. 등록과 스킬이 정렬되면 0 으로 끝나고, 분석 엔진이 없어도 0 이다.
   - 등록(registration:claude_code)이나 스킬이 missing·config_drift → 설정 수리가 필요하다(3 단계).
   - 등록은 aligned 인데 이 세션에 툴이 없음 → 재시작·재연결만 하면 된다(5 단계). doctor 는 지금 세션의 연결을 증명하지 못한다.
   - 분석 엔진(Hopper·Ghidra·IDA·JADX·Kuna) 없음 → 그 엔진이 필요한 작업에만 영향이 있다. 정적 JavaScript 분석은 둘 다 필요 없다. 다른 소프트웨어를 설치하지 않는다.
3. **계획 보기** (읽기 전용):
   ```bash
   npx -y rea-agents@6.7.0 setup --client claude_code --dry-run --json
   ```
   plannedActions 의 대상 경로·백업·변경 내용을 사용자에게 그대로 보여준다. 사용자 전역 설정이다 — Claude Code 사용자 설정 파일(보통 홈의 .claude.json)에 MCP 서버 항목 rea 를 더하고(기존 설정은 보존·백업하고, Windows 에서는 cmd.exe /d /c npx 형태로 등록된다), 홈의 .claude/skills/reverse-engineer-anything 스킬을 설치하거나 교체한다.
4. **승인 후 적용**: 사용자가 명시적으로 승인("진행" 등)한 뒤에만 같은 범위로 실행한다. 침묵이나 모호한 답은 승인이 아니다.
   ```bash
   npx -y rea-agents@6.7.0 setup --client claude_code --yes
   ```
   `--install-hopper` 는 따로 필요하고 따로 승인받은 경우에만 붙인다.
5. **재시작**: Claude Code 를 다시 시작하도록 안내한다(MCP 등록은 시작할 때 읽는다). 재시작하면 이 대화는 이어지지 않으므로, 떠나기 전에 원래 요청(대상과 알고 싶은 것)을 한 줄로 정리해 보여주고 다시 시작한 뒤에 그 요청을 한 번 더 말해 달라고 부탁한다. 요청을 다시 받으면 REA 툴이 실제로 나타났는지 확인한 뒤 조사를 이어간다. 계속 안 보이면 setup 을 반복하지 말고 클라이언트의 MCP 시작 오류를 본다.

등록 전에도 로컬 JavaScript·Electron 대상(폴더 또는 ASAR)은 CLI 로 바로 조사할 수 있다(툴 등록과 네이티브 엔진이 필요 없다). 웹 대상에는 이 경로가 없다. 아래 명령은 사전 승인 목록에 없으므로 평소 권한 규칙대로 처리된다. CLI 의 JSON 은 전체 분석 결과라 매우 클 수 있으니 파일로 받고, 그 파일 전체를 Read 하지 않는다. 요약 보기만 읽는다:

```bash
npx -y rea-agents@6.7.0 analyze-javascript-application <절대경로> --json > <증거파일>
node "${CLAUDE_PLUGIN_ROOT}/scripts/rea/make-view-request.mjs" <증거파일> <요청파일>
npx -y rea-agents@6.7.0 inspect-analysis-view <요청파일>
```

- 리다이렉트(`>`)는 Bash 도구에서 실행한다. Windows PowerShell 5.1 의 `>` 는 출력을 UTF-16 으로 다시 써서 JSON 을 못 쓰게 만든다.
- `<증거파일>` 과 `<요청파일>` 은 6 의 "파일 위치" 규칙대로 OS 임시 폴더에 둔다.
- 두 번째 줄은 업스트림 레시피의 jq 변환(증거를 inline source 로 감싸 summary 보기를 요청)을 node 만으로 하는 변환기다. jq 를 설치하지 않는다. 플러그인 경로가 채워지지 않아 변수 참조가 그대로 보이면, 설치된 플러그인 폴더에서 `scripts/rea/make-view-request.mjs` 를 찾아 절대경로로 쓴다.
- 다른 보기(모듈 목록, 모듈 하나)는 같은 변환기에 `--view '<JSON 객체>'` 를 붙여 요청 파일만 다시 만든 뒤 세 번째 줄을 다시 실행한다. view 모양은 업스트림 references/javascript-applications.md 의 예시를 따른다.

## 4. 웹 대상 (URL)

웹 페이지는 REA 의 웹 툴로만 조사한다. 다른 브라우저 MCP·WebFetch·직접 접속으로 대신하지 않는다. REA 가 연결돼 있지 않으면 3 의 절차로 먼저 연결하고, 연결할 수 없으면 웹 조사는 못 한다고 알리고 멈춘다(위의 CLI 는 로컬 JavaScript 트리·ASAR 전용이라 웹의 대체 경로가 아니다).

1. **브라우저는 사용자가 띄운다**: 평소 쓰는 프로필이 아닌 별도 프로필의 브라우저를 loopback(127.0.0.1) 원격 디버깅(CDP) 포트와 함께 직접 실행하고 그 안에서 대상 페이지를 열어 달라고 안내한다. 평소 프로필을 쓰면 로그인된 세션이 조사에 노출된다. 이 커맨드는 브라우저를 실행하지도 포트를 열지도 않고, REA 의 launch 모드로 브라우저를 새로 띄우게 하지도 않는다(연결 모드만 쓴다). 포트 번호는 사용자가 알려 준다.
2. **누가 동작을 하느냐로 고른다** (업스트림 SKILL.md "Route the target first", references/runtime-observation.md):
   - 사용자가 직접 조작하는 동안 보기: `list_browser_targets` 로 열린 페이지를 찾고, 고른 대상에 `inspect_web_page` 또는 `observe_web_session` 을 쓴다. 이 관찰은 수동이다. REA 가 클릭·이동·페이지 JavaScript 실행을 한 것처럼 보고하지 않는다.
   - 에이전트가 클릭·입력·이동을 해야 하면: 필요한 동작만 선언한 `capture_browser_scenario` 하나. 연결 모드는 먼저 선택한 페이지를 `start_url` 로 이동시켜 저장하지 않은 입력이 사라질 수 있으니 실행 전에 사용자에게 알린다.
3. 툴 이름은 이 커맨드가 고정한 업스트림 스킬의 것이다. 실제로는 연결된 서버가 광고하는 툴과 입력 스키마만 쓴다.

## 5. 벤치마킹 조사 — 7축 체크리스트

경쟁·참고 앱을 비교·벤치마킹하는 요청이면, 조사 전에 업스트림 SKILL.md 의 "Plan broader investigations" 가 요구하는 질문 체크리스트와 근거 원장(finding ledger)을 아래 7축으로 세운다. 표는 축마다 REA 근거로 답할 수 있는 것과 대상만으로는 근거를 댈 수 없는 것을 가른다. 툴 이름은 예시이고, 실제로는 연결된 서버가 광고하는 툴만 쓴다.

| 축 | 관찰 가능 (REA 근거로 답한다) | 관찰 불가 (사유와 함께 적는다) |
| --- | --- | --- |
| 기능 | 배포물에서 읽히는 기능 진입점(라우트·IPC 채널·API·문자열), 사용자가 수행하는 동안 수동 관찰된 동작 | 서버에만 있는 기능, 계정·플래그 뒤에 있어 실행해 본 적 없는 기능, 제품 의도와 우선순위 |
| 디자인 | 배포물 안의 스타일·폰트·아이콘·이미지 자산, 캡처한 스크린샷 | 디자인 의도와 원본 디자인 파일, 캡처하지 않은 상태, 기기별 렌더링 |

| 코드 구조 | 모듈 목록·번들 구성·의존 그래프, 배포된 소스맵, package.json | 소스맵 없이 줄어든 원래 파일 구성과 이름, 저장소 이력·주석·테스트 |

질문은 요청과 대상에 맞게 축마다 직접 세운다(위 표가 질문을 대신하지 않는다). 질문 하나의 상태는 업스트림의 셋, 답함·부분·미해결에 "관찰 불가" 를 더한 넷 중 하나다.

- **관찰 불가**: 이 대상의 배포물이나 수동 관찰로는 어떤 REA 근거로도 답할 수 없는 질문. 사유와 답하는 데 필요한 근거(예: 서버 소스, 계정이 있는 실행 환경)를 한 줄로 적는다. 시도하지 않았거나 도구·엔진이 없어 못 한 질문은 관찰 불가가 아니라 **미해결**이다.
- **커버리지** = 답함 ÷ (전체 - 관찰 불가). 부분은 답함으로 세지 않는다. 관찰 불가 개수는 항상 따로 적는다. 100% 는 관찰 가능한 범위를 다 답했다는 뜻이지 앱을 전부 안다는 뜻이 아니다.
- 결론마다 관찰·추론·미확인을 나누고 Evidence ID 를 인용한다. 정적 분석이 실행을 관찰했다고 쓰지 않는다. 필수 질문이 남은 조사를 완료라고 쓰지 않는다(업스트림 규칙).

## 6. 알아둘 것

- **공급망**: `npx -y` 는 실행할 때마다 npm 에서 `rea-agents@6.7.0` 과 그 의존성을 받아(캐시에 있으면 재사용) 실행한다. 제3자 코드를 내 컴퓨터에서 돌리는 일이다. 버전은 고정했지만 이 패키지에는 shrinkwrap 이 없어 하위 의존성 버전까지 고정되지는 않고, 선택 의존성 frida 는 설치 스크립트가 GitHub 에서 네이티브 바이너리를 내려받는다.
- **용량·지연**: 첫 실행은 패키지와 의존성을 npm 캐시에 설치하느라 시간이 걸리고 디스크를 수백 MB 쓴다(패키지 본체는 수십 MB). 3 의 진단(doctor)이 같은 npx 캐시 항목(`rea-agents@6.7.0`)을 이미 채워 두므로, 등록된 서버가 같은 핀을 쓰는 한 등록 뒤 첫 세션 시작에서 다시 내려받는 일은 npm 캐시를 지웠을 때뿐이다.
- **첫 진입**: 업스트림은 setup 이 끝나면 홈의 스킬 폴더에 깔린 스킬이 설명에 따라 자동으로 발화한다. 그 전의 첫 진입은 이 커맨드가 맡는다.
- **Read 사전 승인 범위**: 이 커맨드가 사전 승인하는 Read 는 `rea setup` 이 설치한 스킬 사본 폴더(홈의 `.claude/skills/reverse-engineer-anything`)뿐이다. 플러그인 쪽 vendor 사본을 읽을 때는 평소 권한 규칙대로 확인이 뜰 수 있고, 조사 대상 파일 읽기는 사전 승인하지 않는다. 대상은 신뢰할 수 없는 입력이다.
- **파일 위치**: 증거 파일(CLI JSON, 요청 JSON, export 번들)은 OS 임시 폴더(`os.tmpdir()`) 아래에 새로 만든 폴더에 두고 작업공간에는 쓰지 않는다. 작업공간에는 사용자가 원하는 보고서 파일 하나만 쓴다. 조사가 끝나면 임시 폴더 위치를 알려 준다.
- **원상복구** (이 커맨드는 실행하지 않는다): `claude mcp remove --scope user rea` 로 등록을 지우고, 홈의 `.claude/skills/reverse-engineer-anything` 폴더를 지운다.

## 하지 않는 것

- `rea update`, `rea uninstall`, 전역 설치(`npm install --global`)는 실행하지 않는다. `--client` 가 `claude_code` 가 아닌 setup 도 실행하지 않는다.
- 브라우저를 실행하거나 원격 디버깅 포트를 열지 않는다. 웹 조사에 다른 브라우저 MCP·WebFetch 를 대신 쓰지 않는다.
- CLI 증거 파일 전체를 Read 하지 않는다. 요약·페이지·항목 보기로 읽는다.
- 플러그인 `.mcp.json` 에는 등록하지 않는다 — 등록하면 모든 세션에 REA 툴과 서버 기동이 붙는다.
- 업스트림 스킬 문구를 고치지 않는다. 스킬 사본은 `vendor/rea` 에 바이트 그대로 있고, 버전을 올릴 때는 `scripts/vendor/sync-rea.mjs` 로만 바꾼다.
