# /blindspot

최근 세션 작업을 대상으로 사각지대 점검을 수행한다. 원래 요구사항을 필수 구성요소로 분해하고, 각 구성요소에 실제 산출물/검증 증거가 있는지 스캔한 뒤, 증거가 없거나 불충분한 지점을 "가장 먼저 막히는 지점(earliest blocking hop)"부터 순서대로 보고한다. **발견된 사각지대는 보고만 하고 자동으로 수정하지 않는다(recommend-only).**

이전에는 매 턴 종료마다 Stop 훅(`blindspot-check`)이 자동 발화했으나, 터미널 노이즈를 줄이기 위해 사용자가 원할 때만 부르는 이 커맨드로 전환됐다.

## Arguments

Parse $ARGUMENTS:
- `--since <git-ref>`: 비교 기준 ref (기본값: `HEAD`). 이 ref 이후의 변경을 점검 대상으로 삼는다. 기본값 `HEAD` 는 **미커밋 변경만** 잡으므로, 커밋을 마친 뒤 부르면 점검 대상이 0 이 되어 그대로 종료된다 — 커밋 후 점검은 `--since <base>`(예: `--since HEAD~1`, `--since main`, `--since @{u}`) 로 세션 시작 지점을 지정하라.

## Execution Flow

1. **작업 맥락 수집**:
   - 변경 파일: `git diff --name-only <ref>` + `git diff --name-only --cached`
   - 변경 내용: `git diff <ref>` (요약)
   - 대화 맥락: 이번 세션에서 사용자가 요청한 원래 요구사항
   - 변경이 전혀 없으면(`git diff` 비어 있음) 점검할 대상이 없으므로 그 사실만 보고하고 종료한다.
2. **요구사항 분해**: 이번 작업의 원래 요구사항을 필수 구성요소(엔티티·속성·연결·제약)로 분해한다. 이번 세션에 벤치마킹 ADOPT/REJECT 판정이 있었다면, REJECT 항목도 구성요소로 분해해 "하위기능 단위로 재검토했는가"를 점검 대상에 포함한다(REJECT 결정은 git diff에 없으므로 대화 맥락에서 수집).
3. **증거 스캔**: 각 구성요소에 대해 실제 산출물/검증 증거(변경된 파일, 테스트, 실행 결과)가 있는지 확인한다. 이번 세션에 REJECT/"구현 안 함" 판정이 있었다면, 각 REJECT 항목을 구성요소로 분해해 "부분채택 가능한 조각을 놓쳤는가"를 점검한다. REJECT 결정은 git diff에 안 남으므로 대화 맥락에서 수집한다.
4. **사각지대 리스트업**: 증거가 없거나 불충분한 구성요소를 earliest-blocking-first 순서로 정렬한다.
5. **보고**: 아래 Output Format으로 리포트한다. 자동 수정은 하지 않는다(recommend-only).

## Output Format

반드시 수평선(`---`) 다음 `### 🔍 사각지대 점검` 헤더로 시작하는 별도 블록으로 출력한다 — 본문 문단에 섞지 않는다.

```markdown
---
### 🔍 사각지대 점검

| # | 구성요소 | 증거 상태 | 막히는 지점 |
|---|----------|-----------|-------------|
| 1 | [필수 구성요소] | ❌ 증거 없음 | [왜 먼저 막히는지] |
| 2 | [필수 구성요소] | ⚠️ 불충분 | [무엇이 부족한지] |
```

- earliest-blocking-first 순서로 정렬
- 사각지대가 없으면 헤더 아래 `이상 없음` 한 줄만 출력
- 각 항목은 권고(recommend)이며, 사용자 지시 없이 자동 수정하지 않는다
