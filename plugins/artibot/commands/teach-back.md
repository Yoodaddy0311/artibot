# /teach-back

최근 세션 작업을 바탕으로 학습 코너를 제시한다. 이번 작업의 **바탕이 되는 일반 개념·원리**를 쉬운 말로 설명하고, 그 개념을 묻는 이해 확인 퀴즈를 낸다. 이번 변경의 구현 경과·선택 사유·세부사항이 아니라, 그 주제를 처음 접하는 사람에게 필요한 **전이 가능한 기본 개념 지식**을 다룬다.

이전에는 매 턴 종료마다 Stop 훅(`teach-back`)이 자동 발화했으나, 터미널 노이즈를 줄이기 위해 사용자가 원할 때만 부르는 이 커맨드로 전환됐다.

## Arguments

Parse $ARGUMENTS:
- `--questions N`: 이해 확인 퀴즈 문항 수 (기본값: 3). 양의 정수가 아니면 3으로 폴백한다.

## Execution Flow

1. **작업 맥락 수집**:
   - 변경 파일/내용: `git diff <HEAD>` 요약으로 이번 작업의 주제를 파악
   - 대화 맥락: 이번 세션에서 다룬 개념·기술
2. **주제 도출**: 이번 작업의 바탕이 되는 일반 개념·원리를 1~2개 추린다(예: 훅 디스패치, 멱등성, 락 뮤텍스 등).
3. **설명**: 그 개념을 쉬운 말로 설명한다 — `12세`·`어린이용` 같은 수준 표현은 쓰지 않는다. 이번 변경의 구현 세부·경위가 아닌 일반 개념 지식만 다룬다.
4. **퀴즈 출제**: 이해 확인 퀴즈 N문항을 낸다. 퀴즈도 일반 개념을 묻는 기초 문제로 하고, 이번 작업의 세부사항·경위를 묻지 않는다.
5. **채점(사용자가 답한 경우)**: 틀린 문항은 정답과 해설만 알려주고 끝낸다 — 재시도 요구·만점 게이트 금지. 사용자가 퀴즈에 답하지 않아도 되며 강요하지 않는다.

## Output Format

반드시 수평선(`---`) 다음 `### 📚 학습 코너` 헤더로 시작하는 별도 블록으로 출력한다.

```markdown
---
### 📚 학습 코너

**핵심 개념**: [이번 작업의 바탕이 되는 일반 개념·원리를 쉬운 말로]

**이해 확인 퀴즈**
1. [일반 개념을 묻는 기초 문제]
2. [일반 개념을 묻는 기초 문제]
3. [일반 개념을 묻는 기초 문제]
```

- 설명·퀴즈 모두 이번 변경의 세부사항·경위가 아닌 전이 가능한 일반 개념 중심
- 사용자가 답하면 채점하되, 틀린 문항은 정답+해설만 제공(재시도·만점 게이트 금지)
- 답변은 선택 사항이며 강요하지 않는다
