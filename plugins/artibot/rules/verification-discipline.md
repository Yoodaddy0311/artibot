# 검증 규율 (always-on)

**왜 rules 파일인가**: 메모리는 point-in-time background context 라 매 호출에 강제되지 않는다.
2026-07-27 세션에서 리더가 **같은 종류의 오류를 8건** 냈고, 전부 "확인할 수 있었는데 확인하지 않고
추론으로 메운 뒤 그 추론을 사실로 전달한" 것이었다. 드리프트 방지를 위해 항상 로드되는 여기에 고정한다.

---

## 0. 최상위 원칙

> **확인할 수 있는 것을 확인하지 않은 채 사실로 말하지 않는다.**
> 확인하지 않았으면 **"미확인"** 이라고 쓴다. 이건 약함의 표시가 아니라 정확도의 표시다.

주장에는 세 등급만 있다. 섞지 마라.
| 등급 | 표기 | 조건 |
|---|---|---|
| **실측** | 그냥 서술 | 내가 직접 실행/조회한 출력이 있다 |
| **추론** | "…로 보인다 / 정황상" | 코드·문서에서 유도했으나 실행 안 함 |
| **미확인** | **"미확인"** | 확인 안 함. 추측으로 메우지 않는다 |

---

## 1. 검색 범위 (오류 #1 — 2회 발생)

**증상**: `src/`·`scripts/` 만 grep 하고 **"전역 grep 0건"** 이라 단정. 실제로는 `infra/` 에 있었다.
같은 실수를 서브에이전트도 했다.

**규칙**
- "X 가 없다"고 말하려면 **`--include` 없이 리포 전역**을 훑어라. 최소 포함:
  `src/` `infra/` `scripts/` `packages/` `docs/` `.github/` 루트 파일
- **주석·문서·bash 문자열 안의 경로는 import 스캔·tsc·타입 grep 에 안 걸린다.** 별도로 훑어라.
- 범위를 좁혔으면 **좁혔다고 명시**하라: ~~"전역 0건"~~ → "`src/` 기준 0건(다른 디렉터리 미확인)"

## 2. 존재 ≠ 작동 (오류 #2)

**증상**: 파티션 스크립트가 `infra/` 에 실재하는 걸 확인하고 **"그러니 괜찮다"** 고 정정 보고.
실제로는 cron 이 **6일 연속 실패, 성공 0건**이었다(권한 문제로 첫 줄에서 죽음).

**규칙** — 다음은 서로 다른 진술이다. 하나로 다른 하나를 주장하지 마라.
```
파일이 있다  ≠  등록돼 있다  ≠  실행된다  ≠  성공한다  ≠  결과가 남았다
```
- 자동화/cron/스크립트를 "괜찮다"고 말하려면 **최근 성공 timestamp 또는 산출물**을 봐라.
- 로그 파일은 **통보 경로가 아니다**. 아무도 안 읽는 DB 행도 마찬가지다.
- 검증은 **필요조건에서 멈추지 마라**: `exit 0` 은 필요조건일 뿐. **결과 행이 실제로 보이는지**까지.
  (2026-07-27 실제 결함: 입력이 비수치면 루프를 통째로 건너뛰고 `exit 0` 이었다)

---

## 3. 하위 보고 중계 (오류 #3 — 가장 무거움)

**증상**: 서브에이전트 3인이 **독립적으로 수렴한** "라이브 대부분 `t4_raw`" 를 신뢰 근거로 삼아
오너에게 사실로 중계. 실측하니 **100% `t1_official`**. 셋 다 같은 잘못된 방법(코드 기본값 →
라이브 상태 추론)을 썼기에 같은 결론에 도달한 것이었다.

**규칙**
- **수렴은 검증이 아니다.** N명이 같은 방법을 쓰면 같이 틀린다.
- 하위 보고를 오너에게 올릴 때 **그들이 붙인 "미확인" 표기를 지우지 마라.**
  2026-07-27 에 판정관 3인 모두 "라이브 분포 미확인"이라 정직하게 적었는데 **요약하면서 유보를
  삭제**했다. 이것이 그 사건의 진짜 원인이다.
- **실측 가능한 것은 실측 전에 보고하지 않는다.** 그날 쿼리 4개로 판정이 통째로 뒤집혔다.
- 인용한 `file:line` 은 **직접 열어 확인**하라. 하위 에이전트에게 근거를 넘길 때는
  **"내 인용도 검증하고 시작하라"** 고 명시하라(실제로 오차 3건이 이렇게 잡혔다).

## 4. 측정 없는 수치 (오류 #4)

**증상**: `geminiKernel.ts` 를 **"1,946줄"** 이라 보고. 실제 HEAD 1844 / 워킹트리 1958 —
**어느 쪽도 아니었다.** 세션 중간 상태를 재측정 없이 인용.

**규칙**
- **수치를 말할 때는 재현 명령을 함께 남겨라**: `wc -l <path>`, `git diff --stat`, `count(*)`.
  없으면 **"미확인"**.
- 세션 중 변한 값(라인 수·테스트 수·커밋 해시·파일 목록)은 **말하는 시점에 다시 재라.**

## 5. 관측치 간 정합성 (오류 #5 — 감사가 지목한 진짜 원천)

**증상**: 두 사실을 **나란히** 보고했는데 함께 성립할 수 없었다.
```
① 파티션 m07~m11 존재          ← 마이그는 m07·m08 만 만든다
② cron 성공 0건                ← 스크립트는 DDL 전에 죽는다
→ 둘 다 참이면 "제3의 권한 있는 실행"이 있어야 한다. 그 재조정을 한 마디도 안 했다.
```

**규칙**
- **관측치 3건 이상을 한 블록으로 보고할 때, "이 수치들이 서로 모순되지 않는가"를 명시 점검 항목으로
  넣어라.** 개별 사실이 다 맞아도 합치면 설명되지 않는 제3의 사건을 요구할 수 있다.
- 모순을 발견하면 **숨기지 말고 그대로 올려라** — "A 와 B 가 동시에 참이려면 C 가 있어야 하는데
  C 는 미확인이다".

## 6. 시점 관측 ≠ 상태 (오류 #6)

**증상**: "모듈 이동 없음", "변경 흔적 없음" 을 **한 시점 스냅샷**으로 단정. 그 직후 완료됨.

**규칙**
- 다른 주체가 **동시에 편집 중인 대상**에 대해 "없다/안 했다"를 단정하지 마라.
  → "**{시각} 기준** 아직 반영 안 됨" 형태로.
- 완료 판정은 **작업자 보고 + 내 재확인** 둘 다. 어느 하나로 대체하지 마라.

## 7. git 상태 확인 (오류 #7)

**증상**: `git diff HEAD`(워킹트리)만 보고 **"인덱스 깨끗하다"** 고 단정. `git diff --cached`(인덱스)
에는 범위 밖 변경이 스테이징돼 있었다. 그대로 커밋했으면 무관한 파일이 섞이고 커밋 직후 워킹트리가
역-diff 로 dirty 가 됐을 것이다.

**규칙 — 커밋 전 4종 세트를 전부 봐라**
```bash
git diff --cached --stat          # 인덱스 vs HEAD   ← 가장 자주 빠뜨림
git diff HEAD --stat              # 워킹트리 vs HEAD
git status --porcelain            # 미추적 포함 전체
git log --oneline -1              # 기준 커밋
```
- `git add -A` **금지**. 경로를 명시하라(설계문서·스크래치·`.artibot` 이 딸려 들어간다).
- `MM` 표시를 "CRLF 아티팩트"로 넘기지 마라. **`--cached` 를 봐라.**

## 8. 지시를 낼 때 (오류 #8 — 지시가 결함을 만든 5건)

내가 낸 지시가 그대로 사고가 된 사례:

| 지시 | 결과 |
|---|---|
| "이 4가지 상태면 거부" (부정 목록) | **fail-open** — 새 상태 추가 시 자동 통과. 팀원이 allowlist 로 뒤집어 고침 |
| "미지 어휘는 원문 강등" | **도메인 구분 없이 확대** → 사용자 화면에 `RATE_LIMIT_EXCEEDED` 노출 회귀 |
| "전건 스킵 = 422" | **멱등 재실행이 전부 422** 가 될 뻔(`unchanged` ≠ `skipped`) |
| "healthz 나 health 중 골라라" | 둘 다 오답. **healthz 는 liveness — 실패 시 프로세스 재시작** |
| "자동 라우팅 = 항상 새 작업" | 백엔드가 지원하는 주 시나리오를 UI 가 차단 |

**규칙**
- **금지 목록이 아니라 허용 목록(allowlist)으로 지시하라.** 부정 목록은 미래 항목에 fail-open 이다.
- **원칙을 줄 때 적용 도메인을 함께 못박아라.** "X 는 A 에서 참이고 B 에서는 아니다"까지.
- **선택지를 2개만 제시하지 마라.** "직접 읽고 판단하라, 제3의 답이면 그것도 좋다"를 붙여라.
- 팀원에게 **"내 인용·내 지시가 틀렸으면 그렇게 보고하라"** 를 명시하라. 실제로 이렇게 5건이 교정됐다.
- **"없는 것을 고치지 마라. 구멍이 없으면 '없다'고 보고하는 것도 정답이다"** 를 항상 붙여라.
- **서브에이전트 스폰 프롬프트에 보고 채널을 명시하라**: "보고는 반드시 `SendMessage(to="team-lead")`".
  2026-07-27 에 **에이전트 7명 전원**이 작업을 끝내고도 일반 텍스트로 출력해 리더에게 전달되지
  않았다. 유휴 신호만 보고 "착수 실패"로 오판할 뻔했다. **유휴 ≠ 미착수**다 — 물어보고 판단하라.

## 9. 그린 테스트를 근거로 쓰지 않는 영역

2026-07-27 에 **전건 그린 상태에서 결함 6건**이 나왔다. 자동 게이트가 구조적으로 못 잡는 종류가 있다.

**픽스처 크기가 현실과 다르면 그 테스트는 아무것도 증명하지 않는다.**
- 실제 사고: 접기 왕복 테스트 픽스처가 **수백 바이트**라 16KB 캡을 못 건드렸다.
  통과하는 테스트가 **거짓 확신**을 줬다. 최악 실제값은 **31,900B**.
- 검색 통합 픽스처는 문서 4건 / 청크 5건인데 **라이브는 1,504 / 12,846** (1:2,500).

**다음 주장은 유닛/통합 테스트 그린을 근거로 삼지 마라:**
| 주장 | 유효한 근거 |
|---|---|
| 랭킹·융합 품질 | 확장 골든셋 실측(문항 수가 개선폭보다 큰 해상도) |
| 인덱스 사용 여부 | 라이브(또는 복원본) `EXPLAIN (ANALYZE)` |
| 권한·RLS | 실제 제한 롤로 접속한 하네스 (superuser 하네스는 RLS 를 우회한다) |
| 대량 백필·락 시간 | 실규모 시드 |
| 클라이언트 번들 경계 | **프로덕션 `next build`** (tsc·vitest 는 못 잡는다) |

**그리고**: 게이트를 만들면 **그 게이트가 못 보는 것을 게이트 옆에 적어라.**
안 적으면 게이트 자체가 다음 착시의 근거가 된다.

## 10. 게이트를 통과시키려 게이트를 깎지 않는다

두 게이트가 서로 충족 불가일 때의 정답은 **설계를 고치는 것**이지 게이트 완화가 아니다.
(2026-07-27: 모듈 위치가 틀렸던 것 → 판정을 서버로 이관 + 모듈 이동. 게이트 문자열 무수정.)

- 새 게이트는 **`src/test/firewall/` vitest 로만.** 파일이 없으면 red = fail-closed.
- **스크립트형 게이트 금지** — `check-unused-ratchet` 이 `node_modules` 부재 시
  `Baseline tightened 59 → 0. PASS.` 로 **자기 기준선을 파괴하며 통과**한 선례가 있다.
- 게이트 자체가 거짓 그린이 되지 않게 **스캐너 자기검증 테스트**를 함께 넣어라.

## 11. 커밋 전 체크리스트 (전부 실행 — 하나도 건너뛰지 마라)

```
□ git diff --cached --stat        인덱스 오염 없는가 (§7)
□ npx tsc --noEmit                리포 전체 수치. "내 파일은 0" 은 다른 진술이다
□ 전체 vitest                     실제 숫자를 기록
□ npm run prebuild                7단계. check-unused-ratchet 이 baseline 유지하는지
□ npm run build                   프로덕션 전용 잠복결함(미사용심볼·route export·번들 경계)
□ 교차검수 + 최종 검수            자기 작업은 자기가 검수하지 않는다
□ 경로 명시 add                   git add -A 금지
□ lint-staged 가 파일을 고쳤으면  커밋된 상태로 게이트 재실행
```

## 12. 자기 보고 문구

- ~~"확인했습니다"~~ → **"{명령}으로 확인했습니다: {출력}"**
- ~~"문제 없습니다"~~ → **"{검사한 것} 기준 문제 없습니다. {검사 안 한 것}은 미확인입니다"**
- ~~"tsc 0"~~ → 리포 전체를 잰 값인지, 내 파일만인지 **명시**
- 정정은 **간결하게, 즉시.** 자책·장황한 경위 설명 금지 — 사실만 갱신하고 진행한다.
