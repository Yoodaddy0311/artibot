> → **`HOOK-VISIBILITY-DESIGN.md` 로 통합됨(2026-09-03).** 이 파일은 이력 보존용이며 정본이 아니다. 흡수·불채택 항목은 정본 §7 출처표 참조.

> 승인 시 별도 작업으로 구현한다. 승인 없이 이 문서를 근거로 로그 코드를 만들지 마라.

- 작성: 2026-09-03, 세션 `9120048e` / 담당 `team-v5-decisions-01sa2u-payload`
- 계기: v5 Observe 계층이 **절반만 살아 있었는데 6주간 아무도 몰랐다.**
  원인 자체(payload 키 불일치)는 같은 세션에서 수리했다. 이 문서는 **원인이 아니라
  "왜 안 보였는가"** 를 다룬다.

## 0. 이 설계가 존재하는 이유 (실측)

| 관측 | 값 | 근거 |
|---|---|---|
| UserPromptSubmit 기여자 6개 중 프롬프트를 못 읽던 개수 | **5 / 6** | 아래 §1 |
| 그 5개가 낸 에러 로그 | **0건** | 에러가 아니라 `return null` 이었다 |
| 라이브에서 결함이 드러난 유일한 통로 | `spawns.ndjson` 의 `route_ledger:"skipped:no-action-text"` **10/10** | `.artibot/ledger/spawns.ndjson`, 04:46Z 이후 16행 |

**핵심 교훈 두 가지.**

1. **훅은 대개 "실패"하지 않는다. 조용히 no-op 한다.**
   `if (!prompt) return null;` 은 예외가 아니다. stderr 도 안 나온다. 종료코드 0 이다.
   → **예외만 남기는 로그였다면 이번 사고를 못 잡았다.** 이 설계의 1순위 요구사항이다.
2. **결함을 드러낸 것은 로그가 아니라 "사유가 붙은 산출물"이었다.**
   `skipped:no-action-text` 라는 **스킵 사유 문자열**이 원장에 남았기 때문에 보였다.
   → 사유를 남기는 스킵은 **가시성 장치 그 자체**다. 성능·소음을 이유로 지우지 마라.

## 1. 무엇을 남길 것인가 — 3계층

로그를 하나 더 만드는 게 아니라, **성질이 다른 세 가지**를 구분한다. 셋을 한 파일에
섞으면 노이즈로 서로를 가린다.

### L1. 크래시 (throw / non-zero exit) — **새 로그의 대상**
현재 `lib/core/hook-utils.js#logHookError` 가 **stderr 로만** 쓴다. Claude Code 가
훅 stderr 를 사용자에게 보여주지 않는 경로에서는 **증발한다.**
→ 파일로 남긴다.

### L2. 조용한 no-op (사유 있는 스킵) — **원장 필드로 남긴다. 로그 파일 아님**
이번 사고를 잡은 형태. `route_ledger:"skipped:<reason>"` 처럼 **해당 도메인의
산출물 안에** 사유를 넣는다.
→ 별도 로그로 옮기지 마라. 산출물 옆에 있어야 읽힌다.
→ **미적용 지점**: UserPromptSubmit 기여자 5종은 `return null` 만 하고 사유를 아무 데도
남기지 않는다. 여기에 L2 를 도입할지가 **결정 H-2**(§6).

### L3. 발화 카운트 (훅이 몇 번 돌았나) — **이 설계의 범위 밖**
"0건"이 "고장"인지 "그런 일이 없었다"인지 구분하려면 분모가 필요하다.
`plugins/artibot/CLAUDE.md` §Existence Audit 이 이미 소유한 주제이고, 그쪽 원장이
정본이다. 여기서 중복 설계하지 않는다.

## 2. 어디에 남길 것인가

```
<projectRoot>/.artibot/ledger/hook-errors.ndjson
```

- **projectRoot 기준**: `hookData.cwd` → `resolveProjectRoot(cwd)`.
  `subagent-handler.js#payloadProjectRoot` 와 **같은 방식**을 쓴다. 세션 중 `cd` 가
  원장 트리를 쪼개지 않게 하려는 기존 규율이고, 두 번째 방식을 만들면 그 규율이 깨진다.
- **cwd 가 없으면 쓰지 않는다.** `process.cwd()` 로 추측하지 마라 — 훅은 어디서든
  스폰될 수 있고, 엉뚱한 리포에 로그를 흘리는 것이 안 남기는 것보다 나쁘다.
- **`~/.claude/` 아래에 두지 않는다.** 전역 위치는 리포 경계를 넘어 프롬프트 파편을
  섞는다(§3).
- **`.gitignore` 로 커밋 차단.** `.artibot/ledger/` 가 이미 무시되는지 확인 후,
  아니면 이 경로를 추가하는 것이 구현 1단계다. (미확인 — 구현 시 실측할 것)

**형식**: NDJSON 1줄 1이벤트. 기존 `spawns.ndjson` 과 같은 형식이라 판독 도구를
재사용할 수 있다.

**필드(허용목록 — 이 목록에 없는 것은 쓰지 않는다):**

| 필드 | 예 | 왜 안전한가 |
|---|---|---|
| `ts` | `2026-09-03T07:11:25.368Z` | — |
| `hook` | `runtime-prompt` | 코드 상수 |
| `event` | `UserPromptSubmit` | 코드 상수 |
| `session_id` | `9120048e-…` | 이미 여러 원장에 있음 |
| `kind` | `throw` \| `timeout` \| `nonzero-exit` | 코드 상수 |
| `error_class` | `TypeError` | 코드 상수 |
| `code` | `ENOENT` | 코드 상수 |
| `message_redacted` | `"Cannot read properties of undefined"` | §3 규칙 통과분만 |

**금지 필드는 §3.**

## 3. 무엇을 남기지 **않을** 것인가 — 로그는 유출 표면이다

> 이 절은 허용목록으로 쓴다. **금지 목록은 미래 항목에 fail-open 이다**
> (rules §8). "이건 안 됨" 이 아니라 "이것만 됨" 이 규칙이다.

**절대 기록 금지 (예외 없음)**

1. **프롬프트 본문 및 그 파생물.** 원문·요약·앞 N자·해시 전부. 길이(정수)도 안 된다 —
   짧은 프롬프트에서 길이는 식별자가 된다.
2. **`transcript_path`, `cwd`, 그 밖의 절대경로.** 사용자명이 들어 있다
   (`C:\Users\<이름>\…`). 경로가 필요하면 `basename` 만.
3. **토큰·비밀값.** `ORCA_AGENT_HOOK_TOKEN`, API 키, `Authorization` 헤더.
   환경변수는 **어떤 것도** 통째로 덤프하지 않는다.
4. **stack trace 전문.** 절대경로를 품는다. `error_class` + 최상단 프레임의
   `basename:line` 까지만.
5. **payload 통째 덤프.** 진단에 편해서 가장 유혹적이고, 위 1~4 를 한 번에 위반한다.

**`message_redacted` 레닥션 규칙 (구현 필수 순서)**

```
1) 절대경로 패턴 제거   : /[A-Za-z]:\\[^\s"']+/ , /\/(?:home|Users)\/[^\s"']+/  → "<path>"
2) 긴 토큰형 문자열 제거 : [A-Za-z0-9_\-]{24,}  → "<redacted>"
3) 길이 상한            : 200자에서 절단
```
순서가 중요하다 — 2번을 먼저 돌리면 경로 조각이 토큰으로 오인돼 부분만 지워진다.

**레닥터 자기검증 테스트를 게이트와 함께 넣는다.** 레닥션이 조용히 깨지면 그때부터
로그가 유출 채널이 된다. `tests/firewall/` 에 vitest 로, 픽스처는 **실제 길이의**
경로·토큰으로 (짧은 픽스처는 아무것도 증명하지 않는다 — rules §9).

## 4. 보존·회전·상한

| 항목 | 값 | 근거 |
|---|---|---|
| 파일 크기 상한 | **1 MiB** | 훅은 프롬프트마다 도는 고빈도 경로. 무제한 성장 금지 |
| 회전 | `hook-errors.ndjson` → `hook-errors.1.ndjson` **1세대만** | 2세대 이상은 사고 조사에 기여한 바가 없다. 필요해지면 그때 늘린다 |
| 보존 | 회전본 1개 + 현재본. **시간 기반 만료 없음** | cron 청소는 그 자체가 감시 대상이 된다(무한 회귀). 크기로만 자른다 |
| 1프로세스당 쓰기 | **최대 1줄** | 훅 하나가 루프에서 로그를 쏟아 회전을 유발해 앞선 증거를 밀어내는 것 방지 |

**회전 시점**: 쓰기 **직전** 크기 확인. 쓴 뒤 확인은 상한을 항상 초과한 뒤에 자른다.

## 5. 조용한 쓰기 실패 방지 — 자기모순 회피

이 로그의 목적은 "조용한 실패를 보이게 하는 것"인데, **로그 쓰기 자체가 조용히 실패**하면
설계가 자기 목적을 배반한다. 실제 선례가 있다: 파티션 cron 이 6일 연속 실패했는데
로그 파일에만 남아 아무도 안 읽었다(rules §2).

**규칙**

1. **로그 쓰기 실패가 훅 본연 동작을 절대 막지 않는다.** 전 경로 try/catch,
   실패 시 훅은 원래대로 진행하고 stdout 을 건드리지 않는다.
2. **실패를 삼키되 무음은 아니다.** 로그 쓰기가 실패하면 **stderr 로** 한 줄 낸다.
   (재귀 방지: 로그 쓰기 실패는 절대 로그 파일에 쓰지 않는다.)
3. **로그 파일 자체가 통보 경로가 아니다.** 아무도 안 읽는 파일은 감시가 아니다.
   → 판독 표면이 함께 있어야 한다. 최소안: `/doctor` 가 최근 24시간 `hook-errors.ndjson`
   행 수를 한 줄로 보고. **이게 없으면 이 설계는 절반짜리다.**
4. **`writeStdout` 보다 뒤에 쓴다.** 훅 응답이 먼저 나가야 로그 I/O 지연이
   프롬프트 지연이 되지 않는다.

## 7. **이 로그가 여전히 못 보는 것** (게이트 옆에 적는다 — rules §9)

적어두지 않으면 이 로그 자체가 다음 착시의 근거가 된다.
**"hook-errors.ndjson 이 비었다"가 "훅이 정상이다"를 의미하지 않는다.**

1. **이번 사고 유형을 못 잡는다.** payload 키 불일치는 throw 가 아니라 `return null`
   이었다. L1 로그는 **0건**이었을 것이고, 그 0건이 "정상"으로 오독됐을 것이다.
   → 이 로그의 실효는 **H-2(스킵 사유)가 함께 갈 때**만 성립한다.
2. **훅이 아예 호출되지 않은 경우를 못 잡는다.** 등록 해제·매처 불일치·플러그인
   미설치는 프로세스가 안 뜨므로 로그도 없다. 이건 L3(발화 카운트)의 영역이고
   여기 없다.
3. **타임아웃 절단을 못 잡는다.** Claude Code 가 훅을 SIGTERM 으로 끊으면 훅 자신은
   로그를 쓸 기회가 없다. `kind:"timeout"` 필드는 **디스패처가 자식을 죽일 때만**
   채워지고, 호스트가 디스패처를 죽이면 아무것도 안 남는다.
4. **`cwd` 없는 페이로드의 실패를 못 잡는다.** §2 규칙상 쓸 곳을 못 정해 스킵한다.
   그 스킵은 stderr 로만 나간다.
5. **설치본과 리포의 괴리를 못 잡는다.** 로그는 **실행된 코드**를 반영한다.
   리포를 고쳐도 릴리스+`plugin update` 전에는 라이브가 구코드다. 이번 세션이 정확히
   그 상태다(리포 수리 완료, 라이브 미반영).
6. **레닥션이 과하게 지운 경우를 알려주지 않는다.** `<redacted>` 만 남은 메시지는
   진단 가치가 0인데, 그 사실이 로그에 표시되지 않는다.

## 8. 구현 순서 (승인 후)

1. `.gitignore` 로 `.artibot/ledger/hook-errors*.ndjson` 커밋 차단 — **가장 먼저.**
   레닥션이 완벽해도 커밋되면 영구 노출이다.
2. 레닥터 + 자기검증 테스트(`tests/firewall/`, 실제 길이 픽스처).
3. 쓰기 함수(회전·상한·try/catch·1줄 상한) + 테스트.
4. `logHookError` 에 배선 — 기존 stderr 동작은 **유지**하고 파일 쓰기를 추가한다.
   stderr 를 파일로 **대체**하지 마라.
5. `/doctor` 판독 한 줄.
6. H-2 승인 시: 스킵 사유 카운터 별도 설계.
