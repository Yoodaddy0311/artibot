## 2. 정의

- **분자**: `assistant` 엔트리의 `message.content[]` 중 `type=tool_use` 이고 `name === 'AskUserQuestion'` 인 블록. 고유 tool_use id 기준, 엔트리 uuid 중복(재개 세션이 복사한 옛 엔트리)은 첫 사본만. 문자열 검색이 아니라 JSON 파싱이다.
- **D1** `nonToolResultUserTurns`: `type=user` 엔트리 중 tool_result 만 담은 것을 뺀 전부(계획서의 거친 정의). 하네스 주입(meta, 팀원 메시지, 작업 알림)이 대부분을 차지한다.
- **D2** `typedBroad`(주 분모): D1 에서 meta·compaction 요약·작업 알림·팀원(peer) 메시지·자동 이어가기·로컬 명령 에코·중단 표식·예약 발화·알 수 없는 origin 을 뺀 것. 남는 것 = 슬래시 명령(`command`) + 라벨된 사람 입력(`human_explicit`) + 라벨 없는 평문(`human_unlabeled`).
- **D3** `typedStrict`: D2 중 호스트가 `origin.kind=human` 으로 명시한 것만.
- `plusQueued`(민감도): 입력 중에 큐에 들어간 타이핑 프롬프트(`queued_command` 첨부)로서 같은 세션의 user 엔트리에 없는 것을 D2 에 더한 값. 전체 35건 중 1건이 user 엔트리와 같은 문장이라 제외됐고 창 합계 34건이 더해진다. 이 분모(D2 에 창별 26·4·4·0건을 더한 값)로 나눈 호출/100 은 손계산으로 34/665 = 5.11, 3/231 = 1.30, 7/271 = 2.58, 0/17 = 0 이다. 같은 정의의 도구 필드가 `callsPer100TypedPromptsPlusQueued` 인데 F1 실행에서는 출력하지 않았고, 경계를 태그 시각으로 둔 실행(A)에서 5.1205 / 1.2931 / 2.583 / 0 을 보았다. §1 표에는 넣지 않았다.
- **창**: 엔트리는 **자기 타임스탬프**의 창에 속한다(시작 포함·끝 제외). 세션 단위 재배정(`bySessionStart`)은 §4-3.
